# Music Finder Bot

Telegram-бот (aiogram 3, long polling) для поиска и скачивания музыки.

- **Поиск**: пишешь исполнителя и/или название — бот показывает варианты кнопками
  («Исполнитель — Название · 3:45») по 8 на страницу, до 60 штук, `◀️ стр. 2 / 8 ▶️`.
- **Очередь**: нажатый трек встаёт в очередь («🕐 В очереди: 2-й»), при загрузке видна полоса
  прогресса ▰▰▰▱▱. До `MAX_PER_USER` треков на человека, повторное нажатие игнорируется.
- **Обложки**: трек приходит с картинкой альбома.
- **Кэш**: трек, однажды отправленный в Telegram, дальше пересылается мгновенно по `file_id`,
  без повторного скачивания.
- **Ссылки**: трек, альбом или плейлист YouTube / YouTube Music / SoundCloud (до 30 треков).
- **Инлайн-режим**: `@бот название` в любом чате — трек отправляется прямо туда.
- **Доступ по приглашению**: незнакомцу бот отвечает «запрос отправлен», владельцу приходит
  кнопка «✅ Разрешить / 🚫 Отклонить». `PUBLIC=1` — бот для всех.
- **Для владельца**: `/stats`, `/users`, `/allow <id>`, `/deny <id>` и оповещения в Telegram,
  когда YouTube блокирует сервер, ломается поиск или три загрузки подряд не удались.

Источники:
- Поиск: Яндекс Музыка (если задан `YANDEX_TOKEN`) → YouTube Music (раздел «Песни») → SoundCloud.
- Загрузка: Яндекс Музыка напрямую, YouTube и SoundCloud через yt-dlp. Если YouTube не даёт
  скачать, тот же трек ищется на SoundCloud, а YouTube 30 минут не трогается.

```
bot.py            # Telegram: команды, очередь, инлайн-режим, доступ
sources.py        # поиск и скачивание (Яндекс, YouTube Music, YouTube, SoundCloud)
storage.py        # SQLite: кэш file_id, пользователи, события для /stats
requirements.txt  # зависимости
.env.example      # список переменных окружения
```

## Переменные окружения

| Переменная     | Обязательна | Что это |
|----------------|-------------|---------|
| `BOT_TOKEN`    | да          | токен бота от [@BotFather](https://t.me/BotFather) |
| `ADMIN_ID`     | желательно  | твой Telegram id (узнать: `/id` в боте). Без него бот открыт для всех, нет `/stats`, оповещений и загрузки новых треков в инлайн-режиме |
| `PUBLIC`       | нет         | `1` — бот для всех, без запроса доступа |
| `YANDEX_TOKEN` | нет         | OAuth-токен Яндекс Музыки — и поиск, и скачивание. Полные треки только с Яндекс Плюс |
| `DB_PATH`      | нет         | где хранить базу, по умолчанию `data/bot.db` |
| `MAX_PARALLEL` | нет         | сколько треков качать одновременно, по умолчанию `1` (на 256 МБ — только 1) |
| `MAX_PER_USER` | нет         | сколько треков один человек может держать в очереди, по умолчанию `30` |
| `YT_PROXY`     | нет         | прокси только для скачивания с YouTube, например `socks5://127.0.0.1:40000` |

Как получить `YANDEX_TOKEN`: https://yandex-music.readthedocs.io/en/main/token.html

## Инлайн-режим: включить в @BotFather

1. `/setinline` → выбрать бота → текст-подсказку, например `название трека…`
2. `/setinlinefeedback` → выбрать бота → `Enabled` — без этого бот не узнает, какой трек
   выбрали, и не сможет его загрузить.

Новый трек загружается через чат владельца (`ADMIN_ID`): бот без звука отправляет туда файл,
берёт его `file_id` и сразу удаляет сообщение. Треки из кэша отправляются мгновенно.

## Запуск на своём сервере (systemd)

```bash
git clone https://github.com/Hon1ks/music_finder_bot /opt/music_finder_bot
python3 -m venv /opt/music_finder_bot/.venv
/opt/music_finder_bot/.venv/bin/pip install -r /opt/music_finder_bot/requirements.txt
```
Юнит — с токеном через `systemd-creds`, `StateDirectory=music-finder-bot` и
`DB_PATH=/var/lib/music-finder-bot/bot.db`. Обновление:
`sudo -u musicbot git -C /opt/music_finder_bot pull && systemctl restart music-finder-bot`.

## Деплой на FadeHost (Free, 256 МБ)

FadeHost деплоит из GitHub-репозитория: находит `requirements.txt` → ставит Python-зависимости
→ запускает `python bot.py`. ffmpeg уже есть в контейнере. **Важно**: FadeHost сам выкатывает
и запускает бота после каждого `git push` — не держи его одновременно с другим запуском
(один токен → конфликт `getUpdates`). И YouTube блокирует скачивание с IP FadeHost.

```bash
npx fadehost login
npx fadehost apps create --repo https://github.com/<you>/music_finder_bot \
  --name music-finder-bot --kind telegram --runtime python \
  --env BOT_TOKEN=... --env TELEGRAM_BOT_TOKEN=... --env ADMIN_ID=... --env DB_PATH=/data/bot.db
npx fadehost apps logs music-finder-bot --follow     # ждём "Start polling"
```
`TELEGRAM_BOT_TOKEN` — тот же токен: FadeHost проверяет по нему приложения типа `telegram`.

## Почему так устроено (256 МБ)

- aiogram 3 при импорте строит pydantic-модели всех типов Telegram — это ~150 МБ, и
  уменьшить это нельзя. Пик при загрузке трека — ~210 МБ (замерено в cgroup с лимитом 256 МБ).
- `yt-dlp` импортируется только при первом обращении к YouTube/SoundCloud; поиск YouTube Music
  идёт прямым запросом без yt-dlp.
- JS-рантайм для yt-dlp (deno) **отключён**: вместе с aiogram он не влезает в 256 МБ (OOM).
- С YouTube берётся m4a и отдаётся без перекодирования; ffmpeg перегоняет только opus/webm.
- Лимит Telegram — 50 МБ на файл, записи длиннее 15 минут пропускаются.

## Ограничения

- YouTube временно блокирует скачивание с IP дата-центров («Sign in to confirm you're not
  a bot»), особенно после всплеска запросов; через несколько часов блок снимается. Cloudflare
  WARP не помогает — его адреса YouTube блокирует так же. На время блока трек берётся с
  SoundCloud: только загрузка с тем же исполнителем, названием и длительностью (±15 сек),
  ремиксы/каверы/slowed/live отсеиваются. У части треков крупных лейблов на SoundCloud только
  превью или DRM — тогда бот честно отвечает «не удалось скачать оригинал».
  Самый надёжный источник — Яндекс Музыка с `YANDEX_TOKEN`.
- Музыка защищена авторским правом. Для публичного бота: жалобы правообладателей могут
  привести к блокировке бота в Telegram, а через `YANDEX_TOKEN` будут качать посторонние —
  для этого нужен отдельный аккаунт Яндекса.
